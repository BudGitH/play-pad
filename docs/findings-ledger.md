# PlayPad — Recursive Findings Ledger

> The anti-whack-a-mole system. Every QA finding is recorded with a **stable ID** so recurrences are counted and **escalated**.
> A bug once is a bug. The same bug three times is a systemic failure — this ledger forces it up the priority chain.

## Escalation rules

| Recurrence | Level                | Required action                                                                                                      |
| ---------- | -------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 1st        | `NEW`                | Fix, or risk-accept with an inline comment. CRITICAL/HIGH block the feature; MEDIUM/LOW may proceed with a fix plan. |
| 2nd        | `TICKET_REQUIRED`    | Open a `PLAY` ticket with **root-cause analysis** + a **systemic fix plan**. Feature can't close until linked.       |
| 3rd        | `TECH_DEBT_PRIORITY` | Escalate into the current cycle's tech-debt budget. Run a codebase-wide scan for the same pattern.                   |
| 4th        | `STOP_SHIP`          | Release blocker. No deploy until the systemic fix is merged and verified.                                            |

## Stable finding ID

`finding_id = <rule-or-category> @ <file-or-pattern>` (NOT line number — lines move). Same rule + same file/pattern ⇒ same id ⇒ increment recurrence.

## Classification dimensions

Every finding is tagged on one or more of: **ACCURACY** (correct output?), **QUALITY** (meets the standard?), **COMPLIANCE** (audit/PII/required docs?), **RISK** (security/availability/data?), **PRODUCT** (meets the business requirement / creates value?), **UX** (usable, clear, pleasant?). The technical dimensions use the severity × dimension response matrix in `docs/WORKFLOW.md`; **PRODUCT/UX** findings are tracked here for **recurrence escalation**, but whether they block is decided by the **Phase 5 product gate** (baseline/value), not that matrix.
