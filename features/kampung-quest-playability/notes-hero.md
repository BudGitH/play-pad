# Notes: hero choice (section C, AC-P8..P10)

> Build notes from the hero-choice workstream, to be folded into the brain docs at CAPTURE. Screenshots in `shots/hero-*.png` (re-take: `node tools/serve.mjs 5603 &` then `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium node features/kampung-quest-playability/shoot-hero.mjs`).

## What was built

- **Picker (AC-P8).** `js/game/hero.js` (`G.Hero`) builds a "Who are you?" block into the title card (`#kqHeroPick`): two big picture cards (Boy / Girl, 112 px tall, our own SVG constants), a `radiogroup` with roving tabindex and arrow keys, inside the title card's existing focus trap. It is shown on a first run (no loaded save) and, with a save, after the first press of New game (the button then reads "Start new game"; the second press starts). Boy is pre-selected, so pressing Start straight away still starts a game: **every existing spec that clicks `#kq button.primary` / `#kqStart` keeps working with no change**. `?hero=girl|boy` pre-selects a card (tests, screenshots). `__kq.start(true)` presses New game twice when needed; `__kq.hero()` = `{ picker, choice, hero }`.
- **Save.** `hero: { gender, style, scarf }` in the save state, sanitised by `KQ.Sim.Hero.sanitize` (own properties only, enum whitelists), written to the `kampung-quest:look` key with the wardrobe so all regions agree; an older look without `hero` keeps the slot's hero; New game clears it. The wardrobe ids are cleaned with the rules of the hero's gender (a boy cannot wear the girl's `dress` id and the other way round).
- **Rules (`js/sim/hero.js`, pure).** Genders, 7 head styles (plain / sporty / flower hijab, ponytail, braids, bun, bob), 8 scarf colours (hijab colour, or the ribbon / hair-tie colour), 6 girl outfits x 8 colours (baju kurung, long dress + leggings, tunic + trousers, abaya, tracksuit, raincoat), all modest (`isModest`: long sleeves, legs covered, never bare shins), the girl's ihram (white modest clothes + white hijab, skin hands). `KQ.Sim.Wardrobe` was refactored to `Wardrobe.make(outfits, default)` so both genders share one tested rule set; its public API and the boy's outfits are unchanged.
- **Girl model (AC-P9).** `F.HERO_GIRL` (cast.js, not in `CAST`): same rig and skeleton as the boy, dressed in place by `dressHero(rig, over, base)` (new `base` arg), with her own face (lashes, softer brows, blush, small smile) and skin hands. New head pieces in `headpieces.js`: `hijab`, `hijab_sport` (band), `hijab_flower` (flower cluster), `girl_ponytail|braids|bun|bob` (hair that frames the face, fringe, ribbon in the scarf colour). New torso prints `dress` and `tunic` in `dress.js`.
- **Faces for both heroes.** `face.hero` draws a finer eye (dark-brown eye, warm lower iris ring, two catch-lights, upper lid line), tapered filled brows, and (girl) three lashes and a rosy small smile. The boy keeps his grin, freckles, brown eyes and cap: the colour-family rule holds (no quills, no joined patch, no green eyes, no muzzle, no belly oval).
- **Tailor (AC-P8/P9).** The wardrobe sheet has a Boy / Girl switch at the top (`.kq-wd-gender`), rebuilds the outfit grid per gender, and for the girl adds "Hair or hijab" (`.kq-wd-style`) and "Scarf and ribbon colour" (`.kq-wd-scarf`, a separate class so `.kq-wd-swatch` still counts only outfit colours). Switching gender gives that hero's own default clothes; Save stores `sim.hero` and `sim.wardrobe`. The barber shows the girl a kind card pointing to the Butik (its cuts are boys' cuts).
- **Ihram (AC-P10).** `Player.applyOutfit` takes a 5th `hero` arg; for the girl it never shows the men's two cloths (`setIhram(false)`), dresses her in `Hero.ihramSpec()` + white hijab, and puts her look back after. The ihram toast and the tailor's ihram card follow the gender. Tahallul for the girl offers only "Snip a lock" (`cut: "lock"`, which `KQ.Sim.Umrah` already knew); the sim's default "trim" on leaving the step is turned into "lock" for the girl in `ritual-flow.js` (the sim itself is unchanged), and the haircut scene does not swap her head piece.
- **Prayer place (AC-P10).** `prayer-flow.js` `hallNow()` returns the women's spot for the girl: the kampung mosque's women's section behind the screen (`NpcGoals.HERO_SPOT_WOMEN` = (-44.2, -22.7); the NPC women's slot there is dropped), or `prayer_spot_women` in Makkah / Madinah. The Talk button offers `prayer_spot_women` to the girl and `prayer_spot` to the boy. `KQ.Sim.Prayer` is untouched.
- **Words / voice.** NPC lines were checked: they say "cucu" (grandchild, neutral) and no line calls the hero "son" / "boy"; the barber's "Handsome!" is only reached by the boy. The hero's spoken voice uses a girl's pitch and a female device voice for the girl (`voice.js`).

## Tests

- `tests/kampung-quest/hero-gender.test.mjs` (in `npm run test:kq`): defaults, sanitize (junk, inherited keys), styles x scarves, modesty of every girl outfit x colour, ihram, per-gender wardrobe cleaning, look key sharing across regions, New game.
- `tests/kampung-quest-hero.spec.mjs`: picker on first run + keyboard + focus trap, choice survives reload, New game shows the picker first, tailor switch + girl styles + back to boy, girl ihram swap and restore (+ tailor waits, lock cut), women's prayer spot free and offered.

## Not done / risks

- The girl's wudu still uses the shared taps (the kampung has a women's wudu room in the world; the prayer flow's guide still points to `wudu_tap_4`).
- Holy cities: the girl uses `prayer_spot_women` (8 m beside the men's spot); there is no separate women's row of NPCs there to frame.
- The live 3D preview on the picker cards was not built (pictures are SVG); cheap and fast to load.
- No hair-colour or skin-tone choice (kept to the brief: outfits, colours, hair / hijab styles).
