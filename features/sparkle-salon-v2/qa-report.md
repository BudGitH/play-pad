## New findings (round 2)

### R2-1 (LOW, quality): the v1 probe check `SS-QA-05` failed once in the re-run

- **Where:** `features/sparkle-salon/probe.mjs` `checkMultiTab`. One run of the final probe on `40e4469` reported `merged = {coins: 56, rev: 3}` instead of `{coins: 8, rev: 100}` (tab A did not adopt the revision-99 save written by tab B before it added a coin). The same check passed in 3 other probe runs, and a dedicated 15-iteration reproduction of the same two-tab steps found 0 failures.
- **Why it is not blocking:** `Save.sync()` / `persist()` and `addCoins` are synchronous and were not touched by this change (the diff has no Save edits); the check is a v1 check. It looks like a cross-tab timing race in the test setup, not a game defect, but it was not root-caused. Repro: run `node features/sparkle-salon/probe.mjs` repeatedly; watch `SS-QA-05`.
- **Action:** noted in the ledger (`checkable-but-unenforced` row, the probes run by hand); poll for the adoption inside the check instead of asserting right after the write when the probe gets its CI job (PLAY-012).

### R2-2 (LOW, quality, observation): four fixed sleeps and a block-level lint disable remain in the new spec

- `tests/sparkle-salon-v2.spec.mjs` keeps 4 `waitForTimeout` calls (1700 ms twice for "the demo must NOT appear" windows, 800 ms twice for the 600 ms long-press), each commented as a duration being tested, and one `eslint-disable max-lines-per-function` for the whole test body list (the same stance as the Brick Buddies v2 spec, DECISIONS 2026-11-22). This is the 2nd recurrence of the spec-level disable (ledger `spec-level-max-lines-disable`, ticket required).

### Observations (no finding)

- The first My Album open at 4x CPU still has one 231 ms longest frame (the first picture is a 30-45 ms task at 1x); the follow-up (serialise the static layers once) is in IDEAS.
- A tester who calls `debug.skipToResults()` marks every step done, so it cannot be used to test recipe accuracy; the spec uses real flows.

## Lens notes

- **ACCURACY:** the recipe now stores a painted or picked slot only when its step is done and Redo resets `run.applied`; sticker bounds are one constant shared by place, drag and drop. Known limit: album stickers are drawn upright at the stored size (ACC-7).
- **QUALITY:** one file, no new dependencies, the new code in the game file has no function over 40 lines; the ratchet reports none new. The harness and screenshot script are committed.
- **COMPLIANCE:** no PII, no network, no new storage keys (the existing save gained an optional `recipe` per look: option ids and sticker positions only, documented in ARCHITECTURE). `_redirects`: the new dev files (`perf/*.mjs`, `shoot-ux.mjs`, screenshots) are all under `features/`, which `_redirects` already sends to `/`; no top-level file and no non-game file in `games/sparkle-salon/` was added, so no change is needed.
- **RISK:** a saved recipe is untrusted input; `cleanRecipe` copies allow-listed ids onto a fresh object, the album picture is a local `data:` SVG built from catalog lookups, and the cache is keyed by the sanitised recipe's JSON.

- The perf numbers are headless Chromium under CPU throttle, not a real iPad; the owner's device check stays open.
