# Kampung Quest — game-local contract

> Constraints for anyone (human or Claude) touching this game. The project-wide rules in the root `CLAUDE.md` / `docs/` still apply; this file adds the game-specific ones. Feature docs: `features/kampung-quest/` (`requirements.md`, `contract.md`, `design-review.md` = the HUD spec, `qa-report.md`, `product-validation.md`). The playability round (map, mounts, hero choice, vehicle life, cards, town life, looks, iPad, Action control) is in `features/kampung-quest-playability/` (`requirements.md`, `test-plan.md`, one `notes-<area>.md` per workstream).

## Hard constraints

- **Build-free classic scripts under `window.KQ`.** No ES modules, no bundler (the `file://` rule, `docs/LEARNINGS.md`). Files load in the order listed in `index.html`; a new file must be added there. Every file is wrapped in `(function (KQ) { "use strict"; ... })((window.KQ = window.KQ || {}))`.
- **Layers (load order):** `js/data` (prayer times, azan captions) → `js/sim` (pure logic, **no THREE, no DOM**, unit-tested: `npm run test:kq`) → `js/figures` (toy cast, poses) → `js/world` (the neighbourhood) → `js/game` (controller, HUD, prayer flow). The game layer may call the others; they never call it.
- **three.js r147 is vendored** (`three.min.js`, UMD). Do not upgrade (no UMD after r160, `file://` rule). `renderer.outputEncoding = sRGBEncoding`, ACES 0.95, PCF-soft shadows.
- **Graceful degradation is mandatory.** `KQ.CAN_FETCH = location.protocol !== "file:"` gates every fetched asset (the photo textures); each has a procedural stand-in. The azan plays from an `<audio>` element (works on `file://`); if it fails to load, a synth chime plus captions replace it. WebGL missing → a friendly card, no crash. Blocked `localStorage` → play without saving, with a notice.
- **Text enters the DOM only through `textContent`** (`KQ.Game.U.el`). `innerHTML` is used only for our own SVG constants (`U.svgFrom`, `pictures.js`). The save is untrusted input (`KQ.Sim.Save` clamps and schema-checks it).
- **Lint:** functions ≤ 40 lines, depth ≤ 3, no empty `catch`, no `console.log`. Split into small functions; do not add files to the lint baseline.
- **Payload < 12 MB** (three.js, ~50 small scripts, 11 photo textures, the azan).

## Child-friendly and religious-accuracy rules (never break these)

- No violence, no fail state, no punishment, no scolding: a wrong tile gives a gentle hint ("Nearly! Next: Ruku (bow).") and the expected tile glows softly, never red or a cross. Every food is halal. Vehicles never hurt the player.
- **Prayer times** are the fixed MUIS values for 26 Nov 2026 in `js/data/prayer-times.js` (source cited there and in `assets/CREDITS.md`). Raka'at: Subuh 2, Zohor 4, Asar 4, Maghrib 3, Isyak 4. Wudu order and the posture sequence come from `KQ.Sim.Prayer` (Shafi'i, as in Singapore): do not re-implement them in the UI.
- **The azan is a real recording** (CC BY-SA 4.0, see `assets/audio/azan_license.txt`). It plays once per prayer, only when the tab is visible, the game is unmuted and unpaused; otherwise captions only. **No music, ever, during the azan** (there is no music in the game at all).
- Both heroes are modest (girl: long sleeves, long skirt or trousers, optional hijab; `Sim.Hero.isModest` is unit-tested over every outfit x colour). Vehicles and animals never hurt anyone; nothing is a fail state.
- The boy hero must keep the colour family (royal blue, tan arms, white gloves, red shoes) with **no quills, no joined eye-patch, no green eyes, no peach muzzle, no belly oval**.

## Rules that are easy to break

- **The pause / hidden gate sits where time and sound are produced** (`Loop.frame`, `Audio.voice`), not in callers (`docs/LEARNINGS.md`, 2026-11-21 audio rows). `Audio.debug()` counts every trigger and every refusal so a probe can assert the lifecycle.
- **Sun times.** The world follows `KQ.PRAYER_TIMES` itself (`js/data/prayer-times.js` must load before the world scripts): sunrise = Syuruk, sunset = Maghrib. `world.update` is given the real clock minute; do not remap it.
- **Prayer flow slows the clock to 25 %** (`FLOW_RATE`) while a flow is active or a prayer screen is open, so a 50-tap Zohor does not run into Asar. A prayer that falls due during a menu is queued (`PrayerFlow.maybeShowCard`) and shown after the menu closes.
- **A fard prayer always outranks the optional sunat prayer.** On `due`, `PrayerFlow.onDue` drops a sunat flow whose screen is closed (the wudu stays clean); `atHall` starts the owed fard prayer over a sunat flow; `nextNote`, the dock and `maybeShowCard` ignore sunat when a fard prayer is due. "Not now" on a sunat screen cancels the flow.
- **Indoor NPCs** (`routine.indoors`) are hidden, but stand at their block's door when the hero is within 15 m (so the first mission giver is always reachable at 07:00).
- **Time of day for tests:** `__kq.setMinute(m)`, `__kq.forcePrayer("zohor")`, `__kq.step(ms)` advance deterministically even when headless rAF is throttled.
- **Characters never move without `Collide.settle`.** Hero, NPCs and their separation all end in a push-out against the colliders (body radius `Player.RADIUS` 0.33, `NpcAgent.RADIUS` 0.31); NPCs are placed with `placeAt` / `stepOut` (free spot, facing open space); stuck means no progress toward the waypoint, and two skips ask for a new route. The camera arm is floored at 0.35 m and rises as it shortens. Audit: `tests/kampung-quest-collision.spec.mjs`.
- **Jump** (Space, touch Jump button, `__kq.input("jump")`): height only (`Sim.Jump`, peak 0.8 m, no double jump), colliders stay horizontal; Space is taken only while `Actions.canJump()`.
- **The crowd is instanced, not rigged.** The 16 cast neighbours are full rigs (14 meshes each); the extras are `KQ.Figures.CrowdKit`: one InstancedMesh per part type (about 25 draw calls for any headcount), poses from the same `F.POSES` functions baked into a (pose, phase bucket, kid) bank. Never add a per-person mesh or light. New activity = a pose in `crowd-poses.js` + a slot kind in `crowd-zones.js` + a curve in `Sim.Crowd`. Extras appear and vanish only out of sight (`mayPop`), never walk except on the walk graph or inside a collider-checked play area, hold seats in the shared `npcs.seats` as `taken === "crowd"`, and are not talkable. Caps per tier are `Sim.Crowd.TIER_CAPS` (120 / 195 / 280) and `HOLY_CAPS` (170 / 290 / 420), with a separate per-frame draw cap `DRAW_CAP` (96 / 170 / 320, nearest first) in `game/crowd.js`; during a teleport / clock jump only the people who stay count against the cap (`liveCount`), or the new town would fill late. Vehicles and parked decor are placed on the first frame, after the crowd is laid out, so `CrowdZones.prune` drops any slot a vehicle now covers; the draw-call budget (< 400 on the low tier, with everything on) is asserted in `tests/kampung-quest-crowd.spec.mjs`, `-vehicles-all`, `-haramain-outskirts` and AC-14. Any seeded random draw goes through `scramble` (murmur3 finaliser) because neighbouring seeds were correlated (every pilgrim got the same dress).
- **Hair / hat outfit:** `hat: "none"` + `hair: "classic"` is the head that goes with the clothes: the hero's own blue cap in the default look, the tailor's (songkok, kufi, a cap in the outfit colour, short hair) otherwise; other combinations come from `Player.HEAD_STYLES`.
- **Wardrobe (tailor).** Outfit + colour are pure data in `js/sim/wardrobe.js` (`KQ.Sim.Wardrobe`: `OUTFITS`, `sanitize`, `choose`, `recolour`, `specFor`, `headFor`), saved as `wardrobe: { wear, tone }` (cleaned by `Save`; the look, barber style + wardrobe, is also kept under `kampung-quest:look` so Singapore, Makkah and Madinah wear the same clothes, and New game clears it). `KQ.Figures.dressHero(rig, overrides)` (`js/figures/dress.js`) rebuilds the hero's parts and atlas from `CAST.hero` + overrides in place (null = the hero's own clothes, which is also what the ihram needs: `Player.applyOutfit` takes the clothes off for ihram and puts them back after). The default look (classic jacket, royal blue) is never repainted, so the colour family rule holds. Sheet: `js/game/wardrobe.js` (`G.Wardrobe.open`, side panel / bottom sheet like the prayer screens, live preview, Save / Cancel, nothing changes until Save, free). Stalls (`js/world/tailor.js`): the Butik at the park edge (`LAYOUT.tailor`), `KQ.HOLY.makkah.tailor` (outside the no-drive plaza) and `KQ.HOLY.madinah.tailor`; interactable id `wardrobe_stall`, poi `tailor` (Madinah's graph id is `tailorMad`, aliased). New outfit = an entry in `OUTFITS` (6-8 colours, modest, long sleeves or knee-length shorts), a silhouette in `wardrobe.js` (game), and a print style in `figures/dress.js` if the existing ones do not fit. Hooks: `__kq.wardrobe()`, `__kq.openWardrobe()`. Spec: `tests/kampung-quest-wardrobe.spec.mjs`; rules: `tests/kampung-quest/wardrobe.test.mjs`.
- **The Action control replaced the floating Talk button.** One fixed control (`#kqAction`, id `kqTalk` kept) with a picture and ONE word from `action-words.js`; the world only points (`#kqPointer`, no text, not clickable). Never add a per-target button or re-project a control over a head. The chooser order comes only from `js/sim/actions.js` (unit-tested in `action-order.test.mjs`); a new action keeps emitting the target shape `{ kind, id, label, aria, x, z, dist, enabled, h }` and adds one row to `action-words.js`. Rest is one tap (`Services.restHere`, energy to full, no dialog); Pray is `PrayerFlow.next()`; the words "Sunat", "Wudu" and "Show me the way" never appear on a button.
- **A minimised card has no sheet.** `RitualUI.minimise()` closes only the sheet and keeps the controller (the owner's `onClose` is NOT called), so close a minimised card with `RitualUI.active.close()`, not by closing a sheet. A rite keeps counting while minimised; `PrayerFlow.refit()` re-lays the same card out on rotate (never close and rebuild it: wudu taps reset). Game-driven movement (Walk for me, the haircut) calls `RitualUI.setBusy(true/false)` and the card tucks away and returns on the edge.
- **The low-tier budget (< 400 draw calls, incl. shadows) now includes events and traffic.** Audited busy views: the bus stop (bus + two traffic cars about 370 to 380), the hawker, the void deck (395 to 398), the kampung street with four traffic cars (320), Makkah's rides lot. Each new vehicle, event prop or person-in-a-car must keep them under; events free their meshes at the end; traffic is pooled; exhaust is one Points; people in cars are crowd instances.
- **Vehicles are rotated-box colliders placed at boot.** Parked vehicles are placed by `Vehicles.prepare(G.Defer)` behind the loading bar, before the crowd's first update and `CrowdZones.prune`; a vehicle is ONE oriented box (`Collide.orientedBox`) kept in `world.colliders`, a driven one is removed while driven, and the bus / traffic boxes are moved in place (`collider.traffic`). Sit every wheel on the plane fitted through the tyre contacts (`Sim.Vehicle.groundPose`), never damp the height. A lamp is a uniform on the shared trim material, not a `THREE.Light`; set `rig.auto = false` when game code drives the brake / reverse lamps.
- **Anything built after the first frame goes through `G.Defer`** (8 ms a frame); one-off GPU work (render-to-texture pictures) uses `{ when: Defer.notPlaying }` and gives its consumer a "finish now" fallback (`Pictures.finishPostures()`).
- **The posture pictures come in two sets, boy and girl** (a white hijab for the girl, chosen by `G.Hero.isGirl()`), rendered one job per picture through the Defer queue: queued after Start is enabled, run only on the title / Pause screens. A prayer screen that needs one sooner calls `finishPostures()`.
- **Men in ihram never get headwear.** `ihramMan` in `crowd-pilgrim-dress.js` skips `matchTour` and keeps the head bare (tested in `crowd-pilgrim.test.mjs`); the hero's ihram follows his or her gender (the girl wears modest white clothes and a white hijab, face and hands uncovered, and cuts "a lock" at tahallul).
- **Tests must not break the real modules.** Never replace a whole module (`G.Mounts = {...}`, then `delete`): patch one method and restore it in `finally`. Check `target.kind` before pressing Interact (a shop counter's menu stays open as a modal and silently blocks events). Layout specs wait for `getAnimations()` to finish and read both rects in one `evaluate` (sheets slide in over 10 px). Run parallel checkouts with their own `PW_PORT`.

## Mobile and touch

- **Touch is first-class** (owner priority): joystick (left), drag-to-look and two-finger pinch on the scene, joystick-rim run (no Run button), Jump button, the fixed Action control (it replaced the floating Talk button; `HudLayout.fitTalk` is gone), the dock, every menu and the wudu / prayer tiles. All HUD buttons are >= 48 px; `touch-action: none` on the stage, `user-select: none`, `-webkit-touch-callout: none`, `contextmenu` blocked, `viewport-fit=cover` plus `env(safe-area-inset-*)`.
- **Quality:** coarse pointers and software GL (SwiftShader / llvmpipe) start on `low`; pixel ratio is capped at 1.5 on touch devices; the loop drops one tier after ~3 s under 40 fps (`Loop.monitor`).
- **Audio on iOS:** `Audio.unlock()` runs on Start and on later touches (resumes a suspended context after returning to the tab); the azan `<audio>` element is created at Start and primed with a silent play+pause inside that gesture. It is NOT created at load (an idle media request keeps the page from ever being "network idle").
- **Prayer panels:** a side panel when the viewport is >= 700 x 340 (the hero stays centred in the rest via `Camera.setShift`), a bottom sheet otherwise. `PrayerFlow.refit()` re-frames / switches the panel on rotation or resize.
- **Phone "lite" HUD:** on phones the status card shows the clock + an icon-only prayer strip (only the due prayer named) and the mission card is a one-line chip; a tap on the chip opens it, a new mission step peeks for 7 s (`HudLayout.toggle/peek`). The status card never folds: it is the Pray button (tap, Enter, Space, or P). In phone landscape the azan card sits in the band above the dock; the Action control stays clear of it (`--kq-azan-side`). **iPad:** `G.Env.ipad` (an iPad UA, or a Mac UA with touch points > 1), `G.Env.tablet` and `G.Env.coarse` (a coarse pointer OR an iPad); the root gets `kq-touch-ui` / `kq-tablet`, so a keyboard iPad (`pointer: fine`) still has the joystick and Jump; iPads start on `low` with a pixel-ratio cap of 1 / 1.25 / 1.5 by tier. Toasts are held while a modal sheet is open. Sheets close on a backdrop tap, except Pause.
- **HUD controls, one entry point each:** Map = the round radar (top right, `#kqMap`, turns with the hero, blips from `map-markers.js`, tap or M), Pray = the prayer-time card (`#kqStatus`), Pause = the corner round button (`#kqDock-pause`, id kept), Missions and Bag = the two-button dock (`#kqDock-missions`, `#kqDock-bag`), food / energy = the labelled bars under the radar (`#kqNeeds`, "Hungry" / "Tired" when low). New menus go in the dock; do not add a second button for an action that already has a home.
- `tests/kampung-quest-mobile.spec.mjs` drives an emulated iPhone 13 (landscape) and Pixel 7 with raw CDP touches.

## How to run and test

- Run: `node tools/serve.mjs 5599` then open `/games/kampung-quest/`, or open `index.html` from disk (`file://`: photo textures are drawn in code).
- `npm run test:kq` (sim unit tests, in CI), `npm run smoke` (all browser specs incl. `tests/kampung-quest-ac.spec.mjs` and `tests/kampung-quest-mobile.spec.mjs`, minus `@slow`), `npm run smoke:core` / `smoke:kq` / `smoke:kq:ac` / `smoke:kq:mobile` (CI runs core and the two kq legs as separate jobs), `smoke:kq:realism` (the guided-tawaf, wardrobe, vehicles-all, Makkah-outskirts and crowd specs; a path-filtered leg in `probes.yml`), `smoke:kq:playability` (the playability round: actions, map, mounts, hero, cards, life, life-holy, looks, ipad, vehicles-ground, vehicle-rig, vehicle-life, figures; not yet in CI), run parallel checkouts with their own `PW_PORT=<port>`, `npm run perf:kq` (the 4x-throttled CPU frame probe; runs in `probes.yml`), `npx eslint games/kampung-quest tests`.
- **Interact priority:** the ranks live in `js/sim/actions.js` (mission business, an owed prayer, the nearest, Say hi, then Rest); the first is the big button, up to two more are chooser tiles. After talking, a service counter wins again until the hero walks 4.5 m away. (`Missions.pickTarget` is still tested but no longer used.)
- **Saves** carry a `rev`; a stale tab is refused (`storage` listener toasts it). A tracker ahead of the clock is rebuilt (`Prayer.update`).
- **Perf:** `stats().calls` includes the shadow pass; static batches are split into 72 m ground cells; the low tier keeps 3 point lights and only the hero + 3 nearest NPCs cast shadows; `boot.js` compiles the start tier and every tier below it behind the loading screen (one frame yielded between tiers; R3-PERF-01), and builds the higher tiers one per 500 ms tick only while the Pause menu is open.
- Screenshots / probes use headless Chromium with `--use-gl=angle --enable-unsafe-swiftshader`; boot takes ~10-15 s in software GL.
